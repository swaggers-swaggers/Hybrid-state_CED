# 2026-09-23：双样本共享参数与 64 步投影监督实现校验

本次只改代码并做功能校验，未启动正式训练。optimizer 的 step 在校验中替换为空操作；M12、三个投影器和置信网络权重逐项保持不变，没有写入训练 checkpoint。

## 实现

- 共享一份模型参数，两个不同回答在 batch 维共同计算，缓存相互隔离。对两个回答的有效损失求和、按监督位置总数归一化，随后每个优化器只更新一次。
- 每次符合 OR 条件的投影后，最多 64 个连续位置执行完整深层输出，全部提供九类 KL 梯度。期间不再投影；本段结束保留缓存值并截断图，再寻找下一个投影位置。短回答或数据区间末尾使用实际剩余长度。
- 每 8 步 activation checkpoint；每条 32 个位置计算浅层和检测头。重算边界不截断梯度，原位 GDN 卷积写入使用独立张量。
- 默认继承一小时训练完成的 `confidence.pt` 全部辅助权重，接续位置 643275。源码快照位于 [一小时实验源码](20260923-detector-1h-source/)。

## 校验结果

CPU 数学、数据对齐、双样本梯度加权、padding、分支和预算测试共 27 项通过。实模型校验见 [verification.json](../../results/verification/20260923-batch64-full/verification.json)，状态 **PASS**。此次记录时，执行时记录的 25 个源码哈希与当前文件一致。

- 只使用投影后第 64 个位置的损失反向，P16/P20/P24 的六个矩阵梯度全部非零且有限；第 65 个位置在窗口外不再给这一投影增加损失。
- 第 64 步六个梯度范数：`[0.0006406052270904183, 0.00037625530967488885, 0.00013039426994509995, 0.00014978155377320945, 0.0002797002671286464, 0.00010500390635570511]`。
- 普通反向和激活重算的损失都为 `0.0158127546`；梯度逐元素比较通过，允许范围 `atol=1e-6, rtol=1e-5`。
- 两条不同 prefix 长度的 h12 与各自独立计算的相对误差约 1.21% / 1.11%；完整输出 logits 相对误差约 0.90% / 1.06%。BF16 分块/批量计算顺序导致小数值差异，不能声称位级相同。
- 修改第二条样本的输入，第一条样本结果完全不变；早退步深层 GDN 状态按要求保持，函数输入缓存未被原位修改。这里只验证状态更新规则，没有计算 GDN 偏差指标。
- 短样本生产循环覆盖 6 / 5 个有效位置：11 个检测头监督位置、2 次投影、9 个后续监督位置、每类参数 1 次模拟更新。
- 完整长度生产循环覆盖 511 / 510 个有效位置：1021 个检测头监督位置、16 次投影、1005 个后续监督位置。所有梯度有限，冻结主干没有参数梯度。
- GPU 峰值 allocated 显存 `4957.39 MiB`（约 4.84 GiB）。这是禁用优化器实际更新的功能校验峰值，不包括真实 AdamW step 才创建的优化器状态，也不是正式训练或推理开销测量。
- 置信阈值设为全部接受 / 全部拒绝时，检测头评估完全一致。

上述生产循环为了覆盖投影分支使用了人为设为可信的标签；其 KL 数值不能解释为新训练效果。没有测得正式训练 UTL 或吞吐提升，不保证利用率达到某个百分比。64 步完整输出监督增加工作量，需要下一次获准训练的真实记录判断速度与质量。
